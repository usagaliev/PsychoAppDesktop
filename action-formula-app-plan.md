## План разработки веб-приложения «Action Formula Coach»

### 1. Подготовка и исследования
- **Синхронизация по видению**: уточнить целевую аудиторию (индивидуальные пользователи, коучи, команды), ключевые сценарии использования и KPI продукта.
- **Анализ контента**: структурировать материалы лекции и конспекта по разделам (конспект, диагностика, чек-листы, упражнения, поддержка), определить уровень детализации и форматы (текст, списки, карточки, формулы).
- **Дизайн-референсы**: собрать moodboard (Make My Plan, SingularityApp, Habitica, Notion, ClickUp, Material Design) с конкретными элементами, которые хотим адаптировать.
- **Функциональные требования**: зафиксировать пользовательские истории (например, «Как пользователь я хочу оценить формулу…», «Хочу сохранить диагностику…»), определить MVP vs. дополнительные фичи.
- **Технические решения**: согласовать стек (React + TypeScript, UI-библиотека/дизайн-система, система управления состоянием, библиотека форм, визуализации, хранилище данных).

### 2. UX/UI и дизайн
- **Информационная архитектура**: спроектировать sitemap (дешборд, диагностика, упражнения, поддержка, профиль/настройки).
- **UX-прототип**: создать low-fidelity wireframes для всех ключевых сценариев (desktop + mobile).
- **UI-макет**: подготовить high-fidelity дизайн в Figma согласно утверждённому промпту; описать состояние компонентов, сетку, отступы, брейкпоинты.
- **Дизайн-система**: определить палитру, типографику, набор UI-компонентов (карточки, кнопки, графики, формы), составить UI-kit и библиотеку иконок.

### 3. Архитектура и подготовка проекта
- **Создание репозитория**: настроить Git, базовый README, правила ветвления и code style.
- **Инициализация фронтенда**: `create-react-app`/Vite + TypeScript, линтеры (ESLint, Prettier), Husky/commit hooks.
- **Структура директорий**: выделить модули (`components`, `pages`, `hooks`, `store`, `utils`, `assets`, `styles`), применить Atomic Design/feature-sliced (по договорённости).
- **Конфигурация UI-фреймворка**: подключить выбранную библиотеку (например, MUI/Chakra/Tailwind) или настроить свои стили (CSS Modules/Styled Components).
- **Инфраструктурные сервисы**: подготовить mock-server или подключить backend/API, выбрать механизм хранения (REST/GraphQL, LocalStorage/IndexedDB для офлайн-режима).

### 4. Реализация функционала (итеративно)
1. **Базовый layout**
   - Header, Footer, навигация, тема, респонсивная сетка.
   - Настройка глобального состояния (например, Zustand/Redux Toolkit/Recoil).
2. **Главная/дешборд**
   - Hero-блок, карточки формулы, CTA, визуализация текущего состояния пользователя.
3. **Диагностика**
   - Форма с полями для цели, слайдерами (0–10), вывод результатов (радиальная диаграмма/гистограмма).
   - Возможность сохранить результат, экспорт (PDF/Markdown), отображение истории.
4. **Упражнения и чек-листы**
   - Каталог карточек, фильтрация по компонентам формулы.
   - Детальные страницы упражнений с шаблонами ответов.
5. **План поддерживающих действий**
   - Списки контактов, чекбоксы commit-devices, настройка напоминаний.
   - Интеграция с внешними сервисами (e-mail/Telegram/Calendar) при необходимости.
6. **Журнал/заметки**
   - CRUD для записей, теги, поиск, связь с результатами диагностики.
7. **Профиль и настройки**
   - Настройка напоминаний, управление данными, экспорт/импорт.

Каждый шаг — отдельная ветка, ревью, покрытие тестами.

### 5. Данные и интеграции
- **Моделирование данных**: описать типы для целей, оценок, упражнений, прогресса.
- **API/Backend** (если нужен): определить эндпоинты, авторизацию, схемы.
- **Сервисы уведомлений**: выбрать провайдера (EmailJS, Firebase, собственный сервер), реализовать отправку напоминаний.
- **Экспорт/импорт**: подготовить шаблоны PDF/MD/CSV, определить формат сохранения в локальном/облачном хранилище.

### 6. Тестирование и качество
- **Юнит-тесты**: React Testing Library + Jest для компонентов и логики.
- **Интеграционные/ e2e**: Cypress/Playwright для ключевых сценариев (диагностика, сохранение, создание планов).
- **Доступность (a11y)**: проверить контраст, ARIA-атрибуты, клавиатурную навигацию.
- **Перформанс**: Lighthouse, оптимизация загрузки (code splitting, lazy-loading), изображения/иконки.

### 7. Документация и поддержка
- **README**: описание проекта, установка, скрипты, окружение.
- **Документация по компонентам**: Storybook или MDX-страницы с примерами использования.
- **Руководство пользователя**: короткий гид, FAQ, ссылки на материалы.
- **План развития**: backlog будущих фич (геймификация, соц-фичи, интеграция с коучами).

### 8. Деплой и сопровождение
- **CI/CD**: настроить GitHub Actions/GitLab CI для билдов, тестов, деплоя.
- **Хостинг**: выбрать площадку (Vercel, Netlify, Render, собственный сервер), предусмотреть окружения (dev/staging/prod).
- **Мониторинг**: подключить аналитики (Google Analytics, PostHog), отслеживание ошибок (Sentry/LogRocket).
- **Поддержка и обратная связь**: внедрить форму сбора отзывов, план апдейтов, таймлайн релизов.

### 9. MVP-объём (для запуска)
1. Главная страница с формулой и CTA.
2. Диагностика с сохранением последнего результата (локально).
3. Каталог упражнений (минимум по одному в каждую категорию).
4. Журнал заметок + экспорт в Markdown.
5. Напоминания через e-mail/локальные уведомления (простая реализация).
6. Минимальный адаптив под мобильные.

После MVP — сбор обратной связи, приоритизация roadmap, расширение функционала (история прогресса, совместная работа, геймификация).
